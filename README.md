# 不打游戏 · maibot-no-games

> 让麦麦**会拒绝游戏邀约**：别人约它打游戏，它一律回绝；它也不会主动邀约、不会上号、不会报位置说"奉陪"。

一个 [MaiBot](https://github.com/Mai-with-u/MaiBot) 插件。在消息**真正发出去之前**检查麦麦自己写的正文，命中「邀约 / 组队 / 承诺参与游戏」的语义就拦下或删改。

---

## 为什么需要它

只靠人设写"不许约人打游戏"是不够的。实测两个反例：

| 现象 | 原因 |
|---|---|
| 人设已经禁了，28 秒后它仍发出「上线开一把」 | 3 分钟前它自己已承诺过，**同一上下文窗口里它在"兑现承诺"**——提示词管不了已经说出口的话 |
| 拦截规则上线后，它连拒绝的话都不说了 | 它的拒绝话术「我不**联机**的」本身含"联机"，被自己的规则拦掉了 |

所以这个插件做两件事：**把它的邀约拦下来**，同时**把它的拒绝话术识别出来并放行**。

## 效果对照

| 麦麦想说的话 | 结果 |
|---|---|
| 「走呗，上线开一把」 | ❌ 拦下（`abort`）或删掉这句（`strip`） |
| 「你说打啥我都奉陪」 | ❌ 拦下 |
| 「我打中单」 | ❌ 拦下 |
| 「QQ语音喊你」 | ❌ 拦下 |
| **「我不联机的，你们玩吧」** | ✅ **放行**（识别为拒绝话术） |
| **「算了我都是自己玩单机的」** | ✅ **放行** |
| **「这游戏这么顶？」** | ✅ 放行（正常聊游戏） |
| **「加载20分钟也太离谱了吧」** | ✅ 放行（正常吐槽） |

## 安装

**方式一：插件市场**

在 MaiBot WebUI 的插件市场搜索并安装。

**方式二：手动**

把本仓库放进 MaiBot 的 `plugins/` 目录（目录里有 `_manifest.json` 和 `plugin.py` 就算一个完整插件），重启 MaiBot，在插件管理里启用。

要求：**MaiBot ≥ 1.3.0**、**插件 SDK ≥ 2.5.0**、**Python ≥ 3.11**。

> 插件目录里还有 `config.toml`，删掉也能加载，运行时会自动生成一份默认配置。

## 兼容性

| 项 | 要求 | 实测 |
|---|---|---|
| MaiBot | ≥ 1.3.0 | **1.3.2** |
| maibot_sdk | ≥ 2.5.0 | **2.9.0** |
| Python | ≥ 3.11 | **3.12.10** |

宿主最低版本定在 **1.3.0** 而不是 1.0.6：插件依赖宿主加载器强制校验
「入口模块导出 `create_plugin` 工厂函数 + 覆写 `on_load`/`on_unload`/`on_config_update`」，
这个行为在 1.3.x 上确认存在；更早版本的加载器规则没有验证过。与其装上之后静默失效，
不如直接装不上并给出提示。SDK 反而放宽到 2.5.0，因为插件只用到
`HookHandler` / `PluginConfigBase` 这些长期稳定的 API。

## 配置

全部配置在 `config.toml`（也可在 WebUI 的插件配置页改）：

| 字段 | 默认 | 说明 |
|---|---|---|
| `plugin.enabled` | `true` | 是否启用插件 |
| `guard.enabled` | `true` | 是否启用拦截（关掉后插件仍加载，只是不拦） |
| `guard.dry_run` | `false` | **试跑模式**：`true` 时只把命中的消息写日志、不拦截 |
| `guard.action` | `"abort"` | `abort`=整条不发；`strip`=删掉命中那一句，其余照发 |
| `guard.extra_patterns` | `[]` | 额外禁止正则，追加到内置规则之后 |
| `guard.extra_keywords` | `[]` | 额外禁止关键词，子串命中即拦 |
| `guard.refusal_patterns` | `[]` | 额外「拒绝话术」正则，命中即放行 |

**建议新装时先开 `dry_run = true` 跑几天**，在日志里搜 `[不打游戏]` 看命中精度，确认没有误杀再关掉。

### 日志怎么看

| 日志 | 级别 | 含义 |
|---|---|---|
| `[不打游戏] 已拦下游戏邀约 ...` | error | 拦下了（含规则、命中片段、字数、120 字摘要） |
| `[不打游戏] 它在拒绝，放行 ...` | info | 识别为拒绝话术，正常放行 |
| `[不打游戏][dry_run] 命中但放行 ...` | info | 试跑模式，只记录 |
| `[不打游戏] guard.action=... 非法 ...` | warning | 配置写错了，已按 `abort` 处理 |
| `[不打游戏] 被拦原文 ...` | **debug** | 完整消息原文，只在 debug 级别出现 |
| `[SendService] 发送消息失败` | error | **这条是拦下的正常伴随现象**，不是故障 |

> **隐私**：消息原文**不会**写进 info / error 日志，只有 debug 级别才有。
> 需要看全文时把日志级别调到 `DEBUG`（`bot_config.toml` 的 `[log].file_log_level`）。

## 工作原理

订阅宿主钩子 `send_service.after_build_message`（出站消息已构建、尚未发送）：

| 返回值 | 效果 |
|---|---|
| `{"action": "continue"}` | 放行 |
| `{"action": "abort"}` | 取消本次发送 |
| `{"action": "continue", "modified_kwargs": {"message": ...}}` | 改写消息后再发 |

三条设计铁律：

1. **只看它自己写的正文** —— 只取 `message["raw_message"]` 里 `type == "text"` 的组件，跳过 `reply` / `at` / `image` / `emoji`。绝不拿被引用的原话或别人的话来判定。
2. **fail-open** —— 任何异常都放行。插件报错绝不能让麦麦变哑。
3. **可试跑** —— `dry_run` 先观察再开启。

## 常见问题

**Q：装上以后麦麦不说话了 / 日志报「缺少 create_plugin 工厂函数」**
A: 插件文件不完整。目录里必须同时有 `_manifest.json` 和 `plugin.py`。
若你是手动复制安装的，确认没漏文件、没多套一层目录。

**Q：日志里出现 `[SendService] 发送消息失败`，是不是坏了？**
A: 不是。这条是消息被主动拦下的正常伴随记录，本插件自己会打
`[不打游戏] 已拦下游戏邀约`，以那条为准。

**Q：它还是说了「来一把」**
A: 三种可能：① `guard.enabled` 被关成 false；② `action` 被填成非法值（会 warn 并回退 abort，
但请检查是不是想填 `strip`）；③ 规则没覆盖这种说法——把那句原话发到 Issues，
或自己加进 `guard.extra_patterns`。

**Q：想让它仍然接话、只把邀约那句删掉**
A: `guard.action = "strip"`。

**Q：想先观察一段时间再拦**
A: `guard.dry_run = true`，日志里会出现 `[dry_run] 命中但放行`，不会真的拦。

**Q：想拦的不只是游戏**
A: 往 `guard.extra_patterns`（正则）或 `guard.extra_keywords`（关键词）里加。
注意同时检查 `guard.refusal_patterns` 是否需要补充"拒绝话术"，否则可能出现
"拒绝被自己规则拦掉"。改完跑一次 `python tests/test_rules.py` 验证没有误杀。

## 已知局限

- 规则是**正则**，判断的是"话里有没有邀约/承诺的意思"，不可能百分百语义准确。漏网的情况请把原话发到 Issues。
- 隐晦表达（例如只说「三缺一」以外的暗语）可能不匹配，可以加进 `extra_patterns`。
- 拦下的消息会让群里"看不到它回话"，这是预期行为；若希望它仍能接话，把 `action` 改成 `strip`。
